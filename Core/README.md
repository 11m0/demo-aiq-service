# Core

Компонент детерминированной проверки ответов, переходов состояния и выбора следующего допустимого действия.

## Контекстная проверка ответа агента

`questionnaire_core.validation` сопоставляет `TurnSuccessResponse` с исходным
`TurnRequest`. Проверка возвращает структурированные нарушения либо поднимает
`InvalidTurnResponseError`; переданный снимок состояния при этом не изменяется.

Текущая политика работает с закрытыми по умолчанию переходами:

- при `answerScope=ACTIVE_QUESTION` обычное сохранение, уточнение и пропуск
  разрешены только для `activeQuestion`;
- при `answerScope=ALL_UNANSWERED` разрешены сохранение нескольких исходно
  незаполненных вопросов и одно уточнение, а пропуски запрещены;
- обычный `SKIP_QUESTION` требует дословного явного отказа отвечать или просьбы перейти
  дальше; одна лишь причина, придуманная моделью, пропуск не разрешает;
- замена уже сохранённого ответа требует `replaceExisting=true` и разрешения
  через совпадающий `answerCorrection` или `replaceableQuestionCodes`; за один
  ход допустима только одна замена, а `ADDITIVE`-дополнение E1 считается отдельно;
- активный вопрос нельзя повторить или сменить без учитываемого изменения состояния;
- для любого типа вопроса допускаются не более двух уточнений; после этого
  `APPLY_DEFAULT_ANSWER` с вариантом `0/3` и причиной
  `CLARIFICATION_LIMIT_REACHED` разрешён активному вопросу `SCALE_0_3`, а
  служебный `SKIP_QUESTION` с причиной `NO_ANSWER_AFTER_RETRY` — активным
  вопросам остальных типов;
- завершение проверяется по локальной проекции статусов после допустимых изменений;
- источники ответа после уточнения должны точно совпадать со всей ожидаемой
  цепочкой, а составное `evidence` — с её дословными фрагментами;
- основание ответа должно быть непустым, дословно происходить из разрешённой
  цепочки сообщений и не содержать команды агенту или внутренние коды вариантов.
  Core не определяет по словам пользователя интерес, частоту, способность,
  предпочтение или выбранную сторону: это семантическая ответственность LLM;
- внутренний смысловой mapper Agent применяет явные продуктовые соответствия уже
  после классификации модели. Core получает обычный `SAVE_ANSWER` и независимо
  проверяет существование варианта, кардинальность, область изменения и переход;
- `assistantReply` проходит guardrail формы и безопасности: уточнение содержит один
  тематически связанный вопрос, не переносит `promptHint`, внутренние коды, ссылки,
  чувствительные данные или пользовательские команды. Обычная разговорная лексика
  разрешена, поэтому модель может коротко отразить сомнение ребёнка и задать живой
  вопрос. Допускаются до двух отфильтрованных предметных слов из текущей цепочки,
  например манга и комиксы; недоверенное произвольное слово можно повторить дословно в
  «ёлочках». Для повторного вопроса после пояснения финальная вопросительная
  часть берётся из активного пункта анкеты; перед ней допустимо краткое пояснение.

Guardrail подтверждает связь реплики с `nextAction`. `questionnaire_core.dialog`
формирует официальный текст из канонического определения, а Backend сохраняет уже
проверенную итоговую реплику.
Для `REASK_QUESTION` Core допускает неизменённый активный вопрос, точную
каноническую реплику или пояснение с доверенным финальным вопросом и пустой патч либо сохранение попутных ответов на исходно
открытые вопросы. Вместе с ними допускается не более одной разрешённой замены
прошлого ответа. Этот переход не считается попыткой смыслового уточнения.

## Скоринг AGE_6_9

`questionnaire_core.scoring` программно рассчитывает 12 шкал по сохранённым
`optionCode`. Обычные вопросы дают 0–3 балла своей шкале, T4 зеркально считает
ансамбль и индивидуальную работу, а E1 добавляет каждой затронутой шкале не более
одного балла. LLM не получает права вычислять или менять эти значения.

Граница между пониманием языка и детерминированными правилами описана в
[`ARCHITECTURE.md`](../ARCHITECTURE.md).
