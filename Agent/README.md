# Agent

Компонент ограниченного агента, клиента языковой модели, промптов и разрешённых
инструментов.

Слой `llm` задаёт независимую от провайдера асинхронную границу:

- полный запрос передаётся одним объектом без серверной сессии внутри клиента;
- структурированный ответ описывается обязательной JSON Schema;
- клиент возвращает сырой текст модели и безопасные метаданные вызова;
- типизированные ошибки сообщают оркестратору, допустима ли повторная попытка;
- `FakeLLMClient` позволяет тестировать сценарии без сети и моков OpenAI SDK.

`OpenAIResponsesClient` реализует эту границу через Responses API. Он отправляет
контекст одним вызовом со строгим `json_schema`, задаёт `store=false`, запрещает
автоматическое усечение входа и отключает встроенные повторы SDK. Адаптер отдельно
обрабатывает отказ модели, ограничение длины, пустой или повреждённый ответ и
переводит исключения SDK в безопасные ошибки без текста ответа провайдера.
Пользовательский `base_url` должен поддерживать именно Responses API.
Вызов выполняется без потоковой выдачи и по умолчанию ограничен
`max_output_tokens=4096`. Температура передаётся в каждый запрос и по умолчанию
равна `0.0`, чтобы уменьшить вариативность извлечения; допустим диапазон от `0.0`
до `2.0`. Адаптер принимает только структурированный текстовый результат; вызовы
инструментов через него не поддерживаются.

Слой `orchestration` содержит строгую внутреннюю модель `AgentDecision`. Модель
возвращает уверенные изменения состояния, при необходимости одно контекстное
уточнение длиной до 240 символов, необязательную короткую подводку
`transitionText` и рекомендацию следующего открытого вопроса
`preferredNextQuestionCode`. Эта первая модель не формирует итоговое действие,
общий `assistantReply`, идентификаторы сессии, версии состояния и время обработки.
После выбора следующего вопроса отдельный вызов модели формулирует цельную
`assistantReply` по истории диалога и проверенной цели.

`QuestionnaireTurnController` выполняет основной вызов `LLMClient`, строго разбирает
JSON без повторяющихся ключей, привязывает каждое сохранение или пропуск к текущей
реплике и принимает только дословное основание из ограниченного набора её
фрагментов. Полная реплика остаётся безопасным запасным основанием для повреждённого
внутреннего значения. Контроллер программно формирует следующее действие, а Core
проверяет предложенное уточнение по длине, Unicode, теме, ссылкам, чувствительным
данным и повторам. Рекомендация следующего вопроса применяется только после
закрытия активного вопроса, если выбранный вопрос всё ещё открыт; иначе контроллер
переходит к первому допустимому. Итоговый вопрос о любимых занятиях остаётся
последним. После свободного рассказа, попутных ответов на другие вопросы или
ответа на вопрос, ранее выбранный вне очереди по теме разговора,
отдельный короткий вызов модели может выбрать более естественный тематический
переход из оставшихся вопросов. Он также используется при недопустимой первой
рекомендации; его сбой оставляет уже проверенный переход без потери ответа.
Обычный однотемный ответ не требует отдельного выбора темы. В рабочем API
после выбора следующего вопроса модель пишет цельную реплику ребёнку: она может
связать реакцию с вопросом без склейки с дословным `questionText`. Core проверяет
её форму и безопасность, а контроллер сверяет названные моделью коды фактически
заданных вопросов с выбранной целью; при отклонении остаётся вопрос анкеты. Этот вызов не
меняет баллы и следующее действие. Первая некорректная генерация решения
отправляется модели на один repair,
а не заменяется видимым шаблоном. Обычные разговорные связки разрешены, если вопрос
сохраняет тематический якорь анкеты; внутренний `promptHint` не может попасть в
реплику ребёнку. Для любого типа вопроса допускаются не более двух живых уточнений.

Когда анкета объявляет `compositeQuestions`, контроллер может выбрать один
общий вопрос о двух близких темах. Сейчас это вопрос про рисование красками
и на планшете после подтверждённого интереса к рисованию. В `nextAction` и
`activeQuestion` передаются основной и сопутствующий коды. Модель сохраняет
оценку отдельно для каждого названного способа; ответ об одном способе оставляет
другой открытым, а неоднозначное короткое подтверждение требует уточнения.
Если и после них ясного ответа нет, контроллер сохраняет для `SCALE_0_3`
автоматический `0/3` через `APPLY_DEFAULT_ANSWER` с причиной
`CLARIFICATION_LIMIT_REACHED`, без пользовательского основания. Для остальных
типов вопросов он завершает вопрос через `SKIP_QUESTION` с причиной
`NO_ANSWER_AFTER_RETRY`; явную просьбу пропустить вопрос обрабатывает отдельно.
Короткое подтверждение, косвенное отношение к занятию, предпочтение вида изображений и
`PAIR_CHOICE` интерпретирует модель с учётом текущего вопроса и контекста
уточнения. Словари фраз и регулярные выражения не назначают вариант ответа.

Для сохранения модель возвращает `INTERPRET_ANSWER`, не внутренний `optionCode`:

- шкала передаётся как прямой `directLevel` либо разрешённый предметный сигнал;
- парный выбор — как сторона `FIRST`/`SECOND` и сила `PREFERRED`/`EXCLUSIVE`;
- обычный и множественный выбор — как позиционные ссылки `V1`, `V2` и далее.

`semantic_mapping` детерминированно переводит эту нормализованную семантику в
варианты конкретного вопроса. Здесь же остаются продуктовые правила: например,
`NEGATIVE_ACTIVITY_ATTITUDE` для `SELF_RATED_SKILL` даёт уровень `1`, а
`POSITIVE_SUBTYPE_INTEREST` для `VISUAL_ATTENTION_FREQUENCY` — уровень `2`.
Прямой уровень имеет приоритет над косвенным сигналом. Модель не видит бизнес-коды
вариантов, а Core проверяет допустимость полученного кода, дословное происхождение
основания и отсутствие команды агенту.
Контроллер добавляет доверенный envelope из
`TurnRequest` и принимает успешный результат только после проверки Core. При
контекстном нарушении контроллер делает не более одного исправляющего вызова с
безопасным перечнем кодов и путей нарушений.
Ожидаемые ошибки провайдера и повторно отклонённые решения возвращаются как
`TurnFailureResponse` без частичного патча и сырого текста модели.

`TurnProcessingLimits` до сетевого вызова проверяет UTF-8 размер полного запроса,
включая динамическую JSON Schema, а до JSON-разбора — размер сырого ответа. По
умолчанию действуют пределы 512 КиБ и 64 КиБ соответственно; их можно внедрить в
контроллер с другими положительными значениями. Данные при превышении не
усекаются.

Слой `prompts` собирает один stateless-вызов из статической системной инструкции
и JSON-контекста. Динамическая JSON Schema ограничивает ответ активным вопросом
или исходно незаполненными вопросами свободного рассказа, разрешённой коррекцией
и формой смысловой интерпретации. В контексте варианты имеют только временные
ссылки `V1`, `V2` и далее; сохранённые ответы также проецируются в эти ссылки.
В массовом извлечении из рассказа разрешены уверенные `INTERPRET_ANSWER` и максимум
одно уточнение по теме, которую ребёнок затронул, но
которую нельзя однозначно сопоставить варианту ответа. Модель может предложить
тематически связанный следующий вопрос, а контроллер вычисляет `nextAction` из
проверенного решения и состояния анкеты.
Если после исправляющего вызова вывод модели остаётся повреждённым, контроллер
возвращает проверяемый `REASK_QUESTION` для активного вопроса без оценки и без
расходования попытки смыслового уточнения. После свободного рассказа такой сбой
ведёт к первому неотвеченному вопросу; рассказ остаётся в истории сессии.

Общая граница ответственности описана в [`ARCHITECTURE.md`](../ARCHITECTURE.md),
а opt-in проверки реальной модели — в [`Evals/README.md`](../Evals/README.md).

Для уточнения промпт передаёт отдельный `clarificationContext`, чтобы модель
учитывала уже сообщённые факты и спрашивала только недостающую информацию.
Из релевантных пользовательских реплик отдельно извлекается отфильтрованный список
предметных терминов `safeClarificationTerms` и допустимых словоформ. Модель может
связать вопрос максимум с двумя такими терминами, например спросить о деталях в
манге и комиксах.
Для произвольного нового слова допустимо только дословное употребление в «ёлочках»;
Core повторно проверяет термин, источник и безопасность; смысловую связь с вопросом определяет модель.
Контроллер добавляет эти пользовательские реплики в provenance итогового ответа.
Для ответа после уточнений `sourceMessageIds` содержит точную полную цепочку, а
видимое `evidence` соединяет её дословные фрагменты через `; `. Поэтому вывод вроде
«хочу выступать, но стесняюсь» не теряет исходное упоминание стеснения.
Для `CLARIFY` Core требует точного совпадения `assistantReply` и проверенного
`clarificationText`. При обычном или составном `ASK_QUESTION`, кроме E1, рабочий
API принимает цельную реплику от [автора вопроса](src/questionnaire_agent/prompts/assistant_reply.py): один
вопрос, ограниченная длина и безопасный текст. При недопустимой формулировке
используется канонический вопрос. Старый путь с `transitionText` остаётся для
прямых вызовов контроллера без подключённого автора реплики.
Если основной агент выводит интерес к ручному творчеству X4 из длительного
изготовления поделок, [отдельный проверяющий вызов](src/questionnaire_agent/orchestration/handcraft_verifier.py)
сверяет этот косвенный признак с текущим ответом ребёнка. Неподтверждённый
признак удаляется до построения ответа; другие изменения хода сохраняются.
Если ребёнок позднее называет длительность уже обсуждённой поделки, та же
проверка может повысить сохранённый X4. Основание соединяет прежнюю короткую
цитату с новой репликой; Core разрешает только источники сохранённого ответа
и текущего хода.
HTTP-приложение создаёт
конкретный клиент и `QuestionnaireTurnController` из проверенных настроек внутри
ASGI lifespan. `POST /v1/turns/process` передаёт контроллеру один полный stateless
запрос и возвращает его типизированный результат; хранение и применение состояния
выполняет backend.
