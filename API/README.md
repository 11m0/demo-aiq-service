# API

Компонент HTTP API, конфигурации процесса, журналирования и сборки приложения.

`APP_ENV` обязателен и принимает `local`, `dev`, `test` или `prod`.

При старте ASGI lifespan создаёт `OpenAIResponsesClient` из `LLM_API_KEY`,
`LLM_MODEL`, необязательного `LLM_BASE_URL`, таймаута, лимита выходных токенов и
`LLM_TEMPERATURE`. Температура по умолчанию равна `0.0`, допустимый диапазон —
от `0.0` до `2.0`. Клиент принадлежит приложению и закрывается при остановке.
Частичная конфигурация отклоняется; только окружение `local` допускает health-only
запуск без LLM.
Если LLM включён, `SERVICE_AUTH_TOKEN` обязателен во всех окружениях. Он должен
содержать от 32 до 512 Bearer-safe ASCII-символов. Безопасное значение можно
сгенерировать командой:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

`GET /health/ready` подтверждает завершённую инициализацию lifespan, но не вызывает
модель и не проверяет доступность внешнего провайдера.

`POST /v1/turns/process` принимает полный `TurnRequest` и обрабатывает ровно один ход
без серверной сессии. Backend остаётся владельцем состояния: хранит анкету, историю
и версии, передаёт их в каждом запросе и атомарно применяет возвращённый патч.

Весь префикс `/v1` требует `Authorization: Bearer <token>`. Проверка выполняется до
чтения HTTP body; один и тот же безопасный ответ HTTP 401 используется для
отсутствующего, повреждённого и неверного токена и содержит
`WWW-Authenticate: Bearer`. `GET /health/live` и `GET /health/ready` публичны.
Ответы `/v1` запрещают кеширование через `Cache-Control: no-store`.

Ответы `SUCCESS` и контролируемые `FAILED` являются результатами предметного
контракта и возвращаются с HTTP 200. HTTP 400 означает повреждённые служебные
заголовки запроса, 401 — ошибку сервисной аутентификации, 413 — превышение
`API_MAX_REQUEST_BYTES`, 422 — невалидный контракт, 500 — безопасную внутреннюю
ошибку, 503 — отсутствие готового контроллера обработки хода. Ошибки валидации и
внутренние исключения не отражают пользовательские или служебные значения в ответе.
Если local health-only запущен без сервисного токена, весь `/v1` fail-closed
возвращает 503.

Токен хранит и отправляет только backend; Frontend не должен получать его ни через
конфигурацию, ни через браузерную сборку. В `prod` Swagger UI, ReDoc и OpenAPI JSON
отключены. Для ротации ML-сервис временно принимает старый токен из
`SERVICE_AUTH_PREVIOUS_TOKEN` вместе с новым `SERVICE_AUTH_TOKEN`: после переключения
всех экземпляров backend предыдущий токен удаляют.

## Ручная проверка

Скрипты требуют PowerShell 7, выполняются из корня проекта и намеренно принимают
только loopback-адреса. В первом терминале запустите API:

```powershell
.\API\scripts\Start-Api.ps1
```

Во втором терминале проверьте инициализацию приложения:

```powershell
.\API\scripts\Test-ApiHealth.ps1
```

Для реального хода должны быть заполнены `LLM_API_KEY`, `LLM_MODEL` и
`SERVICE_AUTH_TOKEN`, а API после изменения `.env` должен быть перезапущен:

```powershell
$serviceToken = Read-Host "SERVICE_AUTH_TOKEN" -AsSecureString
.\API\scripts\Invoke-ApiTurn.ps1 -ServiceAuthToken $serviceToken
```

Клиент отправляет `examples/turn-request.example.json`, проверяет HTTP-контракт,
`correlationId` и `Cache-Control: no-store`. Параметр `-ShowResponse` выводит полный
ответ. Контролируемый `FAILED` имеет HTTP 200 по контракту, но по умолчанию завершает
функциональный smoke-тест ошибкой; `-AllowFailed` разрешает его при проверке только
транспорта и контракта. В local health-only режиме health-проверка проходит, а вызов
`/v1/turns/process` ожидаемо завершается безопасным HTTP 503.
