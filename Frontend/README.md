# Frontend

Веб-интерфейс сервиса анкетирования на React, TypeScript и Vite. Перед созданием
сессии он собирает технические D1/D3, затем предлагает начать со свободного
рассказа или с вопросов по одному, отправляет ответы и показывает возвращённый
снимок анкеты.

Браузер обращается только к маршрутам `/api` backend-приложения. Backend хранит
состояние и вызывает защищённый `POST /v1/turns/process` ML-сервиса.
`SERVICE_AUTH_TOKEN` остаётся на backend и не включается в переменные Vite,
JavaScript или браузерную сборку.

Frontend использует следующие маршруты:

- `POST /api/sessions` — создать сессию;
- `GET /api/sessions/{sessionId}` — восстановить сессию после обновления страницы;
- `POST /api/sessions/{sessionId}/dialog-mode` — выбрать `GUIDED` или `FREE_STORY`;
- `POST /api/sessions/{sessionId}/messages` — отправить новую реплику;
- `DELETE /api/sessions/{sessionId}` — завершить текущую сессию перед новой анкетой.

Идентификатор активной сессии хранится в `sessionStorage`: он переживает обновление
страницы, но не переносится в новую вкладку или следующий сеанс браузера. При
повторной отправке после сетевой ошибки интерфейс сохраняет `messageId`, чтобы
backend мог безопасно обработать повтор запроса. Временная ошибка восстановления не
удаляет идентификатор сессии: интерфейс предлагает повторить загрузку. Идентификатор
удаляется после подтверждённого `SESSION_NOT_FOUND` или успешного завершения сессии
через `DELETE`.

## Локальный запуск

Сначала запустите backend. По умолчанию dev-сервер ожидает его на
`http://127.0.0.1:8001`. Другой адрес можно указать в `Frontend/.env.local`:

```dotenv
VITE_BACKEND_TARGET=http://127.0.0.1:8001
```

Значение должно быть абсолютным HTTP(S) URL без учётных данных, query-параметров и
fragment. Незашифрованный `http` разрешён только для `localhost` и loopback-адресов.

Затем запустите интерфейс:

```powershell
cd Frontend
pnpm install
pnpm dev
```

Откройте <http://127.0.0.1:5173>. Vite проксирует запросы `/api` на backend,
поэтому отдельная настройка CORS для локальной разработки не требуется.

Проверка production-сборки:

```powershell
pnpm typecheck
pnpm build
```

Production-сборка использует относительные адреса `/api`; веб-сервер должен направлять
их в backend приложения.
