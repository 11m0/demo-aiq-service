# aisto-demo-ai-service

Основной stateless ML-сервис для ИИ-ассистента анкетирования.

Понятная схема **текущей работающей версии** — в
[`CURRENT_ARCHITECTURE.md`](CURRENT_ARCHITECTURE.md). Она показывает путь ответа от
браузера до модели и обратно, роль каждого компонента и пока не подключённые части.

Это отдельный проект. Прототип `../ai-questionnaire-assistant` не используется как рабочая директория нового сервиса и остаётся без изменений.

## Локальное окружение

Воспроизводимая подготовка и запуск на Windows/Linux, отдельный файл окружения,
настраиваемые порты и сквозной smoke-тест описаны в
[`DEV_STAND.md`](DEV_STAND.md). Начните с этой инструкции для нового дев-стенда.

Требуется Python 3.12.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.lock.txt
```

`requirements.txt` содержит прямые runtime-зависимости, `requirements-dev.txt` добавляет инструменты разработки, а `requirements.lock.txt` фиксирует проверенное локальное окружение целиком.

Создайте локальный файл с настройками из шаблона:

```powershell
Copy-Item .env.example .env
```

Файл `.env` исключён из Git. В репозиторий следует добавлять только `.env.example` без реальных ключей и других секретов.

Для рабочего маршрута с настроенным LLM сгенерируйте отдельный сервисный токен:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Запишите результат в `SERVICE_AUTH_TOKEN` локального `.env`. Токен должен содержать
от 32 до 512 Bearer-safe ASCII-символов. В `dev`, `test` и `prod` храните его в
менеджере секретов и используйте отдельное значение для каждого окружения.

## Ручной запуск ML API

Локальные smoke-скрипты требуют PowerShell 7, выполняются из корня проекта и
принимают только loopback-адреса. Запустите API в первом терминале:

```powershell
.\API\scripts\Start-Api.ps1
```

Скрипт использует Python из `.venv`, сам собирает `PYTHONPATH` и запускает Uvicorn
в factory-режиме только на loopback-адресе. Для локальной разработки доступен
параметр `-Reload`.

Во втором терминале проверьте публичные health-маршруты:

```powershell
.\API\scripts\Test-ApiHealth.ps1
```

Эта проверка работает и в local health-only режиме. Readiness подтверждает, что
приложение инициализировано, но не выполняет запрос к LLM-провайдеру.

Для проверки полного хода сначала заполните в `.env` значения `LLM_API_KEY`,
`LLM_MODEL` и `SERVICE_AUTH_TOKEN`, затем перезапустите API. Передайте тот же
сервисный токен клиентскому скрипту через защищённый ввод:

```powershell
$serviceToken = Read-Host "SERVICE_AUTH_TOKEN" -AsSecureString
.\API\scripts\Invoke-ApiTurn.ps1 -ServiceAuthToken $serviceToken
```

По умолчанию отправляется `API/examples/turn-request.example.json`. Полный JSON-ответ
можно увидеть с параметром `-ShowResponse`. Предметный `FAILED` с HTTP 200 остаётся
валидным контролируемым ответом API, но функциональный smoke-тест по умолчанию
завершается ошибкой. Для проверки только транспорта и контракта его можно разрешить
параметром `-AllowFailed`. Скрипт не читает `.env`: токен нужно передать через
`SecureString` либо переменную окружения `SERVICE_AUTH_TOKEN`.

## Быстрый сквозной запуск

После настройки `.env` весь локальный стенд запускается одной командой из корня
проекта:

```powershell
.\run.ps1
```

В PyCharm выберите готовую конфигурацию `Локальный стенд` в верхнем списке запусков
и нажмите Run. Если конфигурация ещё не появилась, откройте корневой `run.py`,
нажмите правой кнопкой и выберите `Run 'run'`. Используется интерпретатор проекта
из `.venv`.

Оба launcher-файла запускают ML API, Backend и Frontend в одной консоли. Интерфейс
доступен по адресу <http://127.0.0.1:5173>. Нажатие `Ctrl+C` или кнопки Stop в
PyCharm останавливает всё дерево процессов.

`run.py` также поддерживает Linux и параметры `--env-file`, `--api-port`,
`--backend-port`, `--frontend-port`, `--check`. Для запуска без настроенной модели
нужно явно добавить `--health-only`; сервисный токен для Backend остаётся обязательным.

## Диагностика задержки ответа

После отправки реплики в INFO-журнале появляются события с общим `correlation_id`:

- `backend_turn_total` — полное время обработки сообщения в Backend, включая
  ожидание блокировки сессии (`lock_wait_ms`) и сохранение результата;
- `backend_ml_call` — время HTTP-вызова ML API и разбора его ответа;
- `llm_call` — каждый вызов модели по порядку (`call`), его этап (`stage`),
  причина (`reason`), длительность (`duration_ms`), входные/выходные токены и
  сообщённые провайдером кэшированные входные токены (`cached_input_tokens`);
- `turn_total` — полное время контроллера ML, сумма времени вызовов модели,
  остальное время, число вызовов и суммарные **известные** токены.

Все длительности указаны в миллисекундах. Если провайдер не вернул `usage`,
у соответствующего вызова токены отображаются как `None`; `usage_calls` показывает,
для скольких вызовов доступны счётчики. Измерение Backend начинается после
получения HTTP-запроса и не включает время передачи сообщения от браузера.
`cached_input_tokens=None` означает, что провайдер не сообщил детализацию кэша,
а не то, что кэша нет. Текст реплики, промпт и ответ модели в эти события не
записываются.

Замеры и проверенные варианты ускорения за 29 сентября 2026 года записаны в
[`PERFORMANCE_2026-09-29.md`](PERFORMANCE_2026-09-29.md).

## Раздельный запуск интерфейса

Для рабочего браузерного сценария нужны три процесса. В первом PowerShell запустите
stateless ML API:

```powershell
.\API\scripts\Start-Api.ps1
```

Во втором PowerShell запустите application backend, который хранит сессии и
добавляет сервисный токен только к серверному запросу в ML API:

```powershell
.\Backend\scripts\Start-Backend.ps1
```

В третьем PowerShell запустите Frontend:

```powershell
cd Frontend
pnpm dev
```

Интерфейс будет доступен по адресу <http://127.0.0.1:5173>. Dev-сервер Vite
проксирует только `/api` на `http://127.0.0.1:8001`; защищённый `/v1` и
`SERVICE_AUTH_TOKEN` в браузер не передаются.

Локальный интерфейс использует анкету для 6–9 лет. На первом экране выбирается
возраст, D3 пока ограничен вариантом «Ребёнок самостоятельно». После создания
сессии можно ответить на вопросы по одному или сначала написать короткий рассказ:
во втором сценарии агент извлекает все явно выраженные ответы, а затем продолжает
оставшимися вопросами. Баллы шкал рассчитываются детерминированно в Core без
участия LLM.

Свободную речь интерпретирует LLM, а код переводит нормализованный смысл в
варианты анкеты и проверяет контракты, состояние, provenance и безопасность.
Граница допустимого hardcode описана в
[`ARCHITECTURE.md`](ARCHITECTURE.md). Opt-in набор проверок реальной модели находится
в [`Evals`](Evals/README.md) и не запускается обычной командой `pytest`.

Текущий Backend использует in-memory репозиторий с TTL и блокировкой на сессию для
локальной сквозной проверки. Перед горизонтальным развёртыванием его нужно заменить
общей БД с транзакционной проверкой `stateVersion`. Перед внешней публикацией `/api`
также нужны пользовательская аутентификация, привязка сессии к пользователю и
ограничения частоты, стоимости и параллельности ML-вызовов.

После запуска доступны:

- `GET /health/live` — процесс работает;
- `GET /health/ready` — ASGI lifespan завершил инициализацию ресурсов;
- `POST /v1/turns/process` — обрабатывает один ход диалога;
- `/docs` — описание HTTP API в окружениях, кроме `prod`.

Маршрут обработки хода stateless: backend передаёт полную анкету, текущее состояние,
историю и новую реплику, а сервис возвращает проверенный предлагаемый патч. Состояние
хранит и атомарно применяет backend. Успешное решение и контролируемый отказ агента
возвращаются с HTTP 200 как `SUCCESS` и `FAILED`; слишком большое тело запроса даёт
413, невалидный контракт — 422, внутренняя ошибка — безопасный 500, а неготовый
runtime — 503.

Все маршруты `/v1` защищены до чтения тела запроса. Backend передаёт заголовок
`Authorization: Bearer <SERVICE_AUTH_TOKEN>`. Отсутствующий, повреждённый и неверный
токен получают одинаковый HTTP 401 с `WWW-Authenticate: Bearer`. Health-маршруты
остаются публичными, а ответы `/v1` содержат `Cache-Control: no-store`. Сервисный
токен принадлежит только backend и не должен попадать в Frontend или браузерную
сборку. В local health-only без токена весь `/v1` закрыт ответом 503.

При полной конфигурации `OpenAIResponsesClient` создаётся внутри ASGI lifespan и
закрывается при остановке. Локально приложение можно запустить без LLM-настроек в
health-only режиме; окружения `dev`, `test` и `prod` требуют ключ и модель.
`LLM_TEMPERATURE` управляет вариативностью генерации в диапазоне от `0.0` до `2.0`;
значение по умолчанию `0.0` используется для стабильного извлечения ответов.
`/health/ready` не выполняет платный сетевой запрос и не проверяет текущую доступность
LLM-провайдера.

Для ротации без простоя сначала разверните ML-сервис с новым
`SERVICE_AUTH_TOKEN` и старым значением в `SERVICE_AUTH_PREVIOUS_TOKEN`, затем
переключите backend на новый токен. После обновления всех экземпляров backend
удалите предыдущий токен и повторно разверните ML-сервис.

## Структура проекта

- `Agent` — оркестрация одного хода, LLM-клиенты, промпты и разрешённые инструменты;
- `API` — защищённый stateless HTTP API ML-сервиса;
- `Backend` — browser-facing API, серверные сессии и вызов ML-сервиса;
- `Core` — детерминированная проверка и управление переходами состояния;
- `Contracts` — типизированные модели внешнего контракта;
- `Frontend` — React-интерфейс, работающий через Backend;
- `Evals` — отключённые по умолчанию live-eval сценарии понимания естественных ответов.

Каждый Python-компонент хранит импортируемый пакет внутри собственного каталога `src`.
