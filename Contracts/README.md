# Contracts

Компонент типизированных моделей анкеты, состояния и сообщений между backend и ML-сервисом.

## Контекст текущего хода

`TurnRequest` содержит область извлечения и разрешения на изменение ответов:

- `answerScope` по умолчанию равен `ACTIVE_QUESTION`; значение `ALL_UNANSWERED`
  разрешает извлечение из свободного рассказа только для исходно незаполненных
  вопросов и несовместимо с активным вопросом, коррекцией и ожидаемым уточнением;
- `activeQuestion` связывает незаполненный вопрос с конкретной репликой ассистента;
- `answerCorrection` разрешает адресную замену сохранённого ответа или
  `ADDITIVE`-дополнение выбранных занятий E1;
- `replaceableQuestionCodes` разрешает при активном вопросе исправить по текущей
  реплике один из ранее отвеченных вопросов `SCALE_0_3`, `PAIR_CHOICE` или
  `SINGLE_CHOICE`. По умолчанию список пуст; в одном ответе агента допускается
  не более одной замены ранее сохранённой оценки. Дополнение E1 через
  `answerCorrection=ADDITIVE` в этот лимит не входит.

Backend передаёт `null` для отсутствующих nullable-контекстов. Отсутствие
`answerCorrection` нельзя спутать с пропущенным полем контракта.

Ожидаемое уточнение содержит непустой уникальный список `contextMessageIds`.
Каждый идентификатор указывает на реплику пользователя в `dialogHistory`, которая
предшествует связанной реплике ассистента. Так агент получает точный контекст,
который привёл к уточнению.

Если ответ сохранён после уточнения, его `sourceMessageIds` должен в исходном
порядке содержать все `contextMessageIds`, а затем идентификатор текущей реплики.
Нельзя удалить контекст или добавить произвольное старое сообщение. Строка
`evidence` содержит дословный контекст и выбранный фрагмент текущего ответа,
соединённые через `; `.

После двух безрезультатных уточнений для вопроса `SCALE_0_3` контроллер возвращает
`APPLY_DEFAULT_ANSWER` с вариантом `0/3` и причиной `CLARIFICATION_LIMIT_REACHED`.
Ответ получает `origin=POLICY_DEFAULT` и `defaultReason`, но не получает
`sourceMessageIds` и `evidence`: это правило анкеты, а не вывод из слов ребёнка.
Для остальных типов вопросов контроллер возвращает служебный `SKIP_QUESTION`
с причиной `NO_ANSWER_AFTER_RETRY`; вопрос остаётся без оценки. Явная просьба
пользователя пропустить вопрос также приводит к `SKIP_QUESTION`.

Изменение `REQUEST_CLARIFICATION` содержит обязательный `clarificationText` —
канонический однострочный текст длиной не более 240 символов.

## Канонические тексты анкеты

`questionText` и `clarificationText` проверяются при чтении определения анкеты.
Они должны быть однострочными, содержать хотя бы одну букву или цифру и не более
4000 символов.
Управляющие, bidi, private-use и опасные невидимые Unicode-символы отклоняются;
пробелы по краям не удаляются автоматически, а считаются ошибкой. ZWJ и ZWNJ
разрешены внутри видимого текста для emoji и поддерживаемых письменностей.
